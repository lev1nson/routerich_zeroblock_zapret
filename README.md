# ZeroBlock + Zapret2 для RouteRich / OpenWrt

Автоустановка связки **ZeroBlock + Zapret2** на замену podkop и другим схемам обхода блокировок. Скрипт работает без вопросов: делает бэкап, находит и выключает старые схемы, ставит ZeroBlock, настраивает Zapret2 в связке с ним, заливает списки и проверяет результат.

Проверено на **Routerich AX3000**, прошивка RouteRich 24.10.8 (`mediatek/filogic`, `aarch64_cortex-a53`).

## Совместимость — честно

Скрипт написан на чистом POSIX shell под busybox ash и понимает оба пакетных менеджера OpenWrt: **opkg** (24.10 и старше) и **apk** (25.12 и новее). Архитектуру, LAN-интерфейс, раздел под пакеты и наличие nftables определяет сам.

Но есть жёсткое ограничение, которое скриптом не обходится: **ZeroBlock публикуется только для `mediatek/filogic`**. На [packages.routerich.ru](https://packages.routerich.ru/) других таргетов нет. Поэтому:

| Ситуация | Что будет |
|---|---|
| RouteRich на MediaTek, opkg | Ставится из вложенных `.ipk` |
| RouteRich на MediaTek, apk (25.12) | Ставится из фида роутера |
| Любая прошивка, где ZeroBlock есть в фидах | Ставится из фида |
| Другая архитектура, ZeroBlock недоступен | Скрипт остановится на проверке и объяснит, что делать |

Скрипт не станет ломать вам роутер там, где поставить нечего — он проверяет это до того, как что-либо трогает.

### Нужен sing-box в прошивке

Это отдельное и неочевидное требование. ZeroBlock — менеджер конфигурации, а весь трафик гоняет **sing-box**, и он **не входит в зависимости пакета**: подразумевается, что прошивка его уже несёт. RouteRich несёт (`sing-box-tiny`).

Доставить его отдельно почти невозможно: в распакованном виде это ~28 МБ, а `opkg` проверяет именно распакованный размер — на типичный роутерный `/overlay` в 27 МБ он не влезет физически.

Скрипт проверяет наличие движка в самом начале и отказывается ставить ZeroBlock, которому нечем работать.

### Сколько нужно места

Считано по `Installed-Size` из фида:

| Пакет | Распакованный размер |
|---|---|
| zeroblock | 2.0 МБ |
| luci-app-zeroblock | 1.2 МБ |
| opera-proxy (ставит автонастройка) | 2.1 МБ |
| zapret2 (ставит автонастройка) | 1.2 МБ |
| conntrack и библиотеки | ~0.2 МБ |
| **итого** | **~6.7 МБ** |

Порог для чистой установки — 8 МБ с запасом на временные файлы. Для переустановки поверх уже работающего ZeroBlock хватает 1.8 МБ.

Отдельно: `xray-core` требует 29.6 МБ и на Routerich AX3000 не помещается в принципе. Скрипт его отключает.

## Быстрый старт

На роутере по SSH:

```sh
cd /tmp
wget -O zb.tar.gz https://github.com/lev1nson/routerich_zeroblock_zapret/archive/refs/heads/main.tar.gz
tar -xzf zb.tar.gz
setsid sh routerich_zeroblock_zapret-main/install.sh
```

`setsid` — чтобы обрыв SSH не убил установку на середине. Занимает 5–10 минут, перезагрузка не требуется.

Если связь всё-таки оборвётся, скрипт сам вернёт DNS на место: он ставит обработчик на выход и откатывает подмену резолвера при любом аварийном завершении.

## Что делает скрипт

1. **Проверки.** Root, OpenWrt, совпадение архитектуры с вложенными пакетами, свободное место, интернет.
2. **Бэкап.** `sysupgrade -b` с проверкой целостности архива, плюс `/etc/config`, дамп UCI, список пакетов, состояние сети и nftables. Всё в `/root/zeroblock-migration/<дата>/`.
3. **Установка.** ZeroBlock и luci-app — из вложенных пакетов или фида. Ставится *до* того, как что-либо ломается: если установка не удастся, у вас останется рабочая старая схема.
4. **Старые схемы.** Находит и выключает `podkop`, `zapret`, `passwall`, `openclash`, `xkeen`, `v2raya`, `byedpi`, `nikita` и ещё несколько — останавливает и убирает из автозапуска, список сохраняет в бэкап. Пакеты не удаляет.
5. **Временный DNS.** На время установки переключает dnsmasq на `9.9.9.11` — но только убедившись, что тот реально резолвит, и проверив результат после подмены. Иначе оставляет DNS как есть.
6. **Конфиг.** Пишет проверенный базовый `/etc/config/zeroblock`. `xray_auto_config` включается, только если на `/overlay` есть 35 МБ — иначе демон будет безуспешно ставить xray-core при каждом reload.
7. **Автонастройка.** Ждёт, пока ZeroBlock создаст секции `awg10` (AmneziaWG WARP) и `opera` (opera-proxy), до 5 минут, потом даёт время догрузиться остальным. Секции, которые были до переустановки, но не вернулись сами — например `MESSENGERS` с подсетями Telegram — восстанавливаются из бэкапа.
8. **Community-списки.** Раскладывает по секциям, включая `ai` и `tools`, которые автонастройка не назначает сама.
9. **Свои списки.** Копирует `lists/*.lst` в `/etc/zeroblock/lists/` и подключает как `user_lists`.
10. **Исключения.** Российские ресурсы — банки, госуслуги, Яндекс — в глобальные исключения, чтобы шли напрямую мимо прокси.
11. **Zapret2.** Ставит, если нет. Выставляет `desync_mark` в `0x40000000` — та же метка, что у ZeroBlock. Включает и запускает.
12. **Возврат DNS** с чисткой доменных переопределений от старой схемы.
13. **Проверка.** Статусы служб, sing-box, handshake awg10, контрольные DNS-запросы.

## Переключатели

Все через переменные окружения:

```sh
ZB_SKIP_LISTS=1 sh install.sh
```

Принимаются `1`, `yes`, `true`, `on`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ZB_SKIP_BACKUP` | `0` | Пропустить бэкап. Не надо. |
| `ZB_SKIP_LISTS` | `0` | Не заливать свои списки, только community |
| `ZB_SKIP_EXCLUDES` | `0` | Не заливать российские исключения |
| `ZB_SKIP_DNS_CLEANUP` | `0` | Не трогать доменные переопределения dnsmasq |
| `ZB_SKIP_LEGACY` | `0` | Не выключать старые схемы. Почти наверняка сломает всё |
| `ZB_KEEP_CONFIG` | `0` | Не трогать существующий конфиг, списки и исключения |
| `ZB_PREFER_REPO` | `0` | Ставить из фида роутера, игнорируя вложенные `.ipk` |
| `ZB_REINSTALL` | `0` | Переустановить пакеты, даже если версия совпадает |
| `ZB_INSTALL_TG` | `0` | Поставить `zeroblock-tg` — уведомления в Telegram |
| `ZB_REMOVE_PODKOP` | `0` | Удалить podkop совсем, а не просто выключить |
| `ZB_FORCE` | `0` | Продолжать при нехватке места и отсутствии nftables |
| `ZB_AUTOCONFIG_WAIT` | `300` | Сколько секунд ждать создания секций |
| `ZB_TEMP_DNS` | `9.9.9.11` | Временный DNS на время установки |
| `ZB_BACKUP_DIR` | `/root/zeroblock-migration` | Куда складывать бэкапы |

## Откат

```sh
sh uninstall.sh list    # показать доступные бэкапы
sh uninstall.sh         # мягкий: выключить ZeroBlock, вернуть прежние схемы и DNS
sh uninstall.sh purge   # мягкий + удалить пакеты и конфиги ZeroBlock
sh uninstall.sh full    # полный: sysupgrade -r из последнего бэкапа
```

Мягкий откат возвращает ровно те службы, которые выключал `install.sh` — их список сохраняется в бэкап. Пакеты остаются в системе, включить обратно можно одной командой. Полный откат возвращает **все** настройки роутера на момент бэкапа и требует перезагрузки.

### Пересборка списков

Списки статичны и сами не обновляются, в отличие от community-списков ZeroBlock. Обновить:

```sh
# положить свежие JSON в lists/src/, затем
python3 tools/build-lists.py
```

Конвертер раскладывает сервисы по секциям согласно полю `group`, схлопывает подсети, выбрасывает одиночные IP, уже покрытые CIDR-ами, и отбрасывает IPv6 (на роутере он выключен). Раскладку групп по секциям можно поменять в `SECTION_GROUPS` в начале файла.

| `MESSENGERS` | 12 | 1562 | 89 |

## Как связаны ZeroBlock и Zapret2

Они не конкурируют, а делят работу. ZeroBlock уводит трафик к заблокированным ресурсам через VPN или прокси. Zapret2 обходит DPI для того трафика, который идёт напрямую.

Координация — через метку nftables. ZeroBlock помечает соединения к своим прокси-эндпоинтам меткой `desync_mark` (`0x40000000`), Zapret2 видит метку и не трогает эти соединения повторно. Метка должна совпадать в `zeroblock.engine.desync_mark` и `zapret2.main.desync_mark` — скрипт это обеспечивает.

Если ваш прокси-сервер сам заблокирован по DPI, можно наоборот разрешить Zapret2 работать по нему:

```sh
uci set zeroblock.<секция>.desync_bypass='0'
uci commit zeroblock
/etc/init.d/zeroblock reload
```

## Замечания

**Fake-IP — это нормально.** ZeroBlock отдаёт адреса из `198.18.0.0/15` практически на все домены, включая те, что в исключениях. Маршрут выбирается не на резолве, а в момент подключения: sing-box разворачивает fake-IP обратно в домен и применяет правила, где глобальные исключения стоят первыми.

**Xray-core почти наверняка не влезет.** Пакету нужно около 29.6 МБ, а весь раздел `/overlay` на Routerich AX3000 — 27.6 МБ. Скрипт проверяет место и отключает автоустановку, чтобы демон не пытался ставить его при каждом reload.

**Свой VPN вместо WARP.** По умолчанию поднимается AmneziaWG WARP от RouteRich. Свой сервер добавляется в LuCI: ZeroBlock → секция VPN → «Импорт VPN-интерфейса», принимает обычный wg-quick `.conf`.

**Другая архитектура.** Вложенные пакеты собраны под `aarch64_cortex-a53`. На другом железе скрипт остановится на проверке — положите подходящие `.ipk` в `packages/` или ставьте ZeroBlock из репозитория RouteRich.

**Место на диске.** На Routerich AX3000 после установки остаётся 3–5 МБ из 27.6 МБ. Это тесно: `opkg` при переустановке пакета сначала удаляет старый и только потом проверяет, влезет ли новый — на полном диске так можно потерять рабочий пакет. Поэтому скрипт по умолчанию не переустанавливает то, что уже стоит нужной версии, а принудительная переустановка (`ZB_REINSTALL=1`) сначала считает, хватит ли места.

Если веб-интерфейс всё же не поставился, установка проксирования от этого не страдает — верните его отдельно:

```sh
opkg install luci-app-zeroblock
```

## Диагностика

```sh
logread -e zeroblock | tail -50        # лог демона
cat /tmp/zeroblock-install.log         # лог установки
/etc/init.d/zeroblock status
uci show zeroblock | grep -E "=section"
nft list ruleset | grep 0x40000000     # связка с zapret2
awg show awg10                         # состояние туннеля
```

Если ZeroBlock не появился в меню LuCI — обновите страницу, перелогиньтесь, очистите кэш браузера или откройте админку в инкогнито-окне.

### Пропала секция маршрутизации

Симптом: часть сервисов перестала ходить в обход — например Telegram и Instagram, — хотя YouTube работает.

```sh
uci show zeroblock | grep "=section"
```

Должны быть как минимум `awg10` и `opera`, обычно ещё `MESSENGERS`. Если какой-то нет, возьмите её из бэкапа:

```sh
SRC=$(ls -t /root/zeroblock-migration/*/zeroblock.cfg.bak | head -1)
/etc/init.d/zeroblock stop
awk -v want=MESSENGERS 'BEGIN{q=sprintf("%c",39)}
  /^config /{ n=$3; gsub(q,"",n); inside = ($2=="section" && n==want) }
  inside' "$SRC" >> /etc/config/zeroblock
uci show zeroblock >/dev/null && /etc/init.d/zeroblock start
```

### Проверить, что трафик реально идёт в обход

Не по DNS, а по фактическому адресу выхода. Если у секции включён mixed proxy (`enable_mixed_proxy=1`), с любой машины в сети:

```sh
curl --proxy http://192.168.1.1:2080 https://api.ipify.org   # через секцию
curl https://api.ipify.org                                    # напрямую
```

Адреса должны отличаться. Одинаковые — маршрутизация не работает.
