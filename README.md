# ZeroBlock + Zapret2 для RouteRich / OpenWrt

Автоустановка связки **ZeroBlock + Zapret2** на замену podkop и другим схемам обхода блокировок. Скрипт работает без вопросов: делает бэкап, находит и выключает старые схемы, ставит ZeroBlock, настраивает Zapret2 в связке с ним, заливает списки и в конце проверяет, что обход действительно работает.

---

## Быстрый старт

На роутере по SSH:

```sh
cd /tmp
wget -O zb.tar.gz https://github.com/lev1nson/routerich_zeroblock_zapret/archive/refs/heads/main.tar.gz
tar -xzf zb.tar.gz
setsid sh routerich_zeroblock_zapret-main/install.sh
```

`setsid` — чтобы обрыв SSH не убил установку на середине. Занимает 5–10 минут, перезагрузка не требуется.

Если связь всё-таки оборвётся, скрипт вернёт DNS на место сам: он ставит обработчик на выход и откатывает подмену резолвера при любом аварийном завершении.

## Требования

### ZeroBlock существует только под MediaTek

Жёсткое ограничение, которое скриптом не обходится. На [packages.routerich.ru](https://packages.routerich.ru/) есть только `mediatek/filogic` — ни x86, ни ipq807x, ни ramips.

| Ситуация | Что будет |
|---|---|
| RouteRich на MediaTek, opkg | Ставится из вложенных `.ipk` |
| Любая прошивка, где ZeroBlock есть в фидах | Ставится из фида |
| Другая архитектура | Скрипт остановится на проверке и объяснит, что делать |

Скрипт не станет ломать роутер там, где поставить нечего — он проверяет это до того, как что-либо трогает.

### Нужен sing-box в прошивке

Неочевидное требование. ZeroBlock — менеджер конфигурации, а весь трафик гоняет **sing-box**, и он **не входит в зависимости пакета**: подразумевается, что прошивка его уже несёт. RouteRich несёт `sing-box-tiny`.

Доставить отдельно практически невозможно: в распакованном виде это ~28 МБ, а `opkg` проверяет именно распакованный размер — в типичный роутерный `/overlay` на 27 МБ он не влезает физически.

Скрипт проверяет движок первым делом и отказывается ставить ZeroBlock, которому нечем работать.

### Место на диске

Требование считается по тому, чего в системе ещё нет. Цифры — `Installed-Size` из фида:

| Пакет | Распакованный размер |
|---|---|
| zeroblock | 2.0 МБ |
| luci-app-zeroblock | 1.2 МБ |
| opera-proxy (ставит автонастройка) | 2.1 МБ |
| zapret2 (ставит автонастройка) | 1.2 МБ |
| conntrack и библиотеки | ~0.2 МБ |
| запас на временные файлы opkg | 1.0 МБ |

Совсем чистая система — около **7.7 МБ**. Если opera-proxy и zapret2 уже стоят — **4.3 МБ**.

`opera-proxy` и `zapret2` доставляет автонастройка **после** того, как старые схемы выключены. Не учесть их — значит уронить установку на полпути, когда возвращаться уже некуда.

После установки на AX3000 остаётся 3–5 МБ. Перед установкой чего-либо ещё смотрите `df -h /overlay`.

## Что делает скрипт

1. **Проверки.** Root, OpenWrt, пакетный менеджер, архитектура, nftables, `dnsmasq` с поддержкой nftset, LAN-интерфейс, наличие sing-box, свободное место, интернет.
2. **Бэкап.** `sysupgrade -b` с проверкой целостности архива, плюс `/etc/config`, дамп UCI, список пакетов, состояние сети и nftables. Всё в `/root/zeroblock-migration/<дата>/`, хранятся три последних.
3. **Установка.** ZeroBlock и luci-app — из вложенных пакетов или фида. Ставится *до* того, как что-либо ломается: если установка не удастся, у вас останется рабочая старая схема.
4. **Старые схемы.** Находит и выключает `podkop`, `zapret`, `passwall`, `openclash`, `xkeen`, `v2raya`, `byedpi`, `nikita` и ещё несколько — останавливает и убирает из автозапуска, список сохраняет в бэкап для отката. Пакеты не удаляет.
5. **Временный DNS.** Переключает dnsmasq на `9.9.9.11`, но только убедившись, что тот реально резолвит, и проверив результат после подмены. Иначе оставляет DNS как есть.
6. **Конфиг.** Пишет проверенный базовый `/etc/config/zeroblock` и сбрасывает runtime-состояние демона, иначе при переустановке он считает автонастройку уже выполненной. Существующие секции маршрутизации сохраняются.
7. **Автонастройка.** Ждёт, пока ZeroBlock создаст `awg10` (AmneziaWG WARP) и `opera` (opera-proxy), потом даёт время догрузиться остальным. Секции, которые были до переустановки, но не вернулись — восстанавливает из сохранённой копии.
8. **Секция MESSENGERS.** Автонастройка создаёт только `awg10` и `opera` — проверено на чистой установке. Секции для мессенджеров нет ни в дефолтах пакета, ни на сервере, а без неё списки `messengers` и `meta` назначать некуда: Telegram, Instagram и WhatsApp не маршрутизируются вообще. Скрипт создаёт её из `sections/MESSENGERS.conf`.
9. **Community-списки.** Раскладывает по секциям, включая `ai` и `tools`, которые автонастройка не назначает сама.
10. **Свои списки.** Копирует `lists/*.lst` в `/etc/zeroblock/lists/` и подключает как `user_lists`.
11. **Исключения.** Российские ресурсы — банки, госуслуги, Яндекс — в глобальные исключения, чтобы шли напрямую мимо прокси.
12. **Zapret2.** Ставит, если нет. Сверяет `desync_mark` с тем, что стоит у ZeroBlock. Включает и запускает.
13. **Возврат DNS** с чисткой доменных переопределений от старой схемы — с показом, что именно убрано.
14. **Проверка.** Статусы служб, sing-box, число секций, handshake awg10, DNS, и главное — фактическое сравнение внешнего адреса через прокси и напрямую.

## Переключатели

Через переменные окружения. Принимаются `1`, `yes`, `true`, `on`:

```sh
ZB_SKIP_LISTS=1 sh install.sh
```

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ZB_SKIP_BACKUP` | `0` | Пропустить бэкап. Не надо. |
| `ZB_SKIP_LISTS` | `0` | Не заливать свои списки, только community |
| `ZB_SKIP_EXCLUDES` | `0` | Не заливать российские исключения |
| `ZB_SKIP_DNS_CLEANUP` | `0` | Не трогать доменные переопределения dnsmasq |
| `ZB_SKIP_LEGACY` | `0` | Не выключать старые схемы. Почти наверняка сломает всё |
| `ZB_KEEP_CONFIG` | `0` | Не трогать существующий конфиг, секции, списки и исключения |
| `ZB_PREFER_REPO` | `0` | Ставить из фида роутера, игнорируя вложенные `.ipk` |
| `ZB_REINSTALL` | `0` | Переустановить пакеты, даже если версия совпадает |
| `ZB_REMOTE_LISTS` | `0` | Подключить списки по URL, чтобы ZeroBlock обновлял их сам |
| `ZB_LISTS_URL` | GitHub этого репо | Свой источник для `ZB_REMOTE_LISTS` |
| `ZB_INSTALL_TG` | `0` | Поставить `zeroblock-tg` — уведомления в Telegram |
| `ZB_REMOVE_PODKOP` | `0` | Удалить podkop совсем, а не просто выключить |
| `ZB_FORCE` | `0` | Продолжать при нехватке места, отсутствии nftables и sing-box |
| `ZB_AUTOCONFIG_WAIT` | `300` | Сколько секунд ждать создания секций |
| `ZB_TEMP_DNS` | `9.9.9.11` | Временный DNS на время установки |
| `ZB_BACKUP_DIR` | `/root/zeroblock-migration` | Куда складывать бэкапы |

## Откат

```sh
sh uninstall.sh list    # показать доступные бэкапы
sh uninstall.sh         # мягкий: выключить ZeroBlock, вернуть прежние схемы и DNS
sh uninstall.sh purge   # мягкий + удалить пакеты и конфиги ZeroBlock
sh uninstall.sh full    # полный: sysupgrade -r из последнего бэкапа
```

Мягкий откат возвращает ровно те службы, которые выключал `install.sh` — их список сохраняется в бэкап. Пакеты остаются в системе, включить обратно можно одной командой. Полный откат возвращает **все** настройки роутера на момент бэкапа и требует перезагрузки.

```
├── packages/                     .ipk ZeroBlock 0.8.4-r280 (aarch64_cortex-a53)
├── sections/
│   └── MESSENGERS.conf           секция мессенджеров, если её нет в системе
├── lists/
│   ├── zb-awg10.lst              списки для секции awg10 (VPN)
│   ├── zb-MESSENGERS.lst         списки для секции MESSENGERS
│   ├── zb-opera.lst              списки для секции opera (proxy)
│   ├── exclude-domains.txt       российские домены — напрямую
│   ├── exclude-ips.txt           российские подсети — напрямую
│   └── src/                      исходники в формате podkop/getIPList
└── tools/
    ├── fetch-lists.sh            скачать свежие выгрузки и пересобрать
    └── build-lists.py            пересборка списков из src/
```

### Откуда списки

Три разных источника, их важно не путать:

1. **Community-списки ZeroBlock** — приходят с сервера RouteRich и обновляются сами. `youtube`, `discord`, `meta`, `messengers`, `torrent`, `ai`, `tools` и прочие. Скрипт только раскладывает их по секциям.
2. **Списки из этого репозитория** — `lists/*.lst`, собраны из выгрузок [iplist.my-handbook.ru](https://iplist.my-handbook.ru/ru) (зарубежные ресурсы) и [ru-iplist.my-handbook.ru](https://ru-iplist.my-handbook.ru/ru) (российские). Оба — инстансы проекта [rekryt/iplist](https://github.com/rekryt/iplist). Обновляются командой `sh tools/fetch-lists.sh`.
3. **Исключения** — из того же ru-iplist: банки, госуслуги, налоговая, Яндекс. Идут напрямую мимо прокси.

Исходные JSON лежат в `lists/src/`, готовые списки — обычный текст, открываются и читаются глазами.

### Обновление списков

Одной командой — скачивает свежие выгрузки и пересобирает:

```sh
sh tools/fetch-lists.sh
git diff --stat lists/    # посмотреть, что изменилось
```

Скрипт не тронет рабочие списки, если источник не ответил или прислал мусор. Запускать на своей машине, не на роутере: результат коммитится в репозиторий.

Пересобрать из уже скачанных JSON, без сети:

```sh
python3 tools/build-lists.py
```

### Чтобы ZeroBlock обновлял списки сам

```sh
ZB_REMOTE_LISTS=1 sh install.sh
```

Тогда рядом с локальным файлом в `user_lists` добавится URL из этого репозитория, и ZeroBlock будет перекачивать его по своему расписанию (`update_interval`, по умолчанию раз в сутки). Локальный файл при этом остаётся подключённым и работает без сети — проверено, ZeroBlock объединяет оба источника без конфликтов.

Свой источник: `ZB_LISTS_URL=https://example.com/lists`.

Стоит понимать, что даёт этот режим: списки подтягиваются **из репозитория**, а не напрямую из iplist. То есть свежесть появляется только после того, как кто-то запустит `fetch-lists.sh` и закоммитит результат. Взамен вы получаете зависимость от доступности GitHub у каждого пользователя. Если вы не собираетесь регулярно обновлять списки — проще оставить выключенным и обновлять повторным запуском `install.sh`.

**Важно про URL.** HTTP-клиент ZeroBlock отрезает query-строку — проверено на живом роутере: `https://iplist.my-handbook.ru/?format=text&group=messengers` он запрашивает как `https://iplist.my-handbook.ru/` и получает HTML вместо списка. Поэтому подключать API iplist напрямую нельзя, годятся только URL с путём вроде `raw.githubusercontent.com`.

Конвертер раскладывает сервисы по секциям согласно полю `group`, схлопывает подсети, выбрасывает одиночные IP, уже покрытые CIDR-ами, и отбрасывает IPv6 (на роутере он выключен). Раскладку групп можно поменять в `SECTION_GROUPS` в начале файла.

| Секция | Сервисов | Доменов | Подсетей |
|---|---|---|---|
| `awg10` | 235 | 435 | 205 |
| `MESSENGERS` | 12 | 1562 | 89 |
| `opera` | 224 | 1706 | 405 |
| исключения (РФ) | 51 | 180 | 81 |

## Как связаны ZeroBlock и Zapret2

Они не конкурируют, а делят работу. ZeroBlock уводит трафик к заблокированным ресурсам через VPN или прокси. Zapret2 обходит DPI для того трафика, который идёт напрямую.

Координация — через метку nftables. ZeroBlock помечает соединения к своим прокси-эндпоинтам меткой `desync_mark` (`0x40000000`), Zapret2 видит метку и не трогает эти соединения повторно. Метка должна совпадать в `zeroblock.engine.desync_mark` и `zapret2.main.desync_mark` — скрипт это обеспечивает и сверяет.

Если ваш прокси-сервер сам заблокирован по DPI, можно наоборот разрешить Zapret2 работать по нему:

```sh
uci set zeroblock.<секция>.desync_bypass='0'
uci commit zeroblock
/etc/init.d/zeroblock reload
```

## Замечания

**Fake-IP — это нормально.** ZeroBlock отдаёт адреса из `198.18.0.0/15` практически на все домены, включая те, что в исключениях. Маршрут выбирается не на резолве, а в момент подключения: sing-box разворачивает fake-IP обратно в домен и применяет правила, где глобальные исключения стоят первыми. Проверять обход по выводу `nslookup` бессмысленно — только по фактическому адресу выхода.

**Xray-core не влезет.** Пакету нужно 29.6 МБ, а весь `/overlay` на AX3000 — 27.6 МБ. Скрипт отключает его автоустановку, иначе демон будет безуспешно пытаться поставить его при каждом reload.

**Свой VPN вместо WARP.** По умолчанию поднимается AmneziaWG WARP от RouteRich. Свой сервер добавляется в LuCI: ZeroBlock → секция VPN → «Импорт VPN-интерфейса», принимает обычный wg-quick `.conf`.

**Осторожно с переустановкой пакетов.** `opkg --force-reinstall` сначала удаляет пакет и только потом проверяет, влезет ли новый — на тесном диске так теряется рабочий пакет. Поэтому скрипт по умолчанию не переустанавливает то, что уже стоит нужной версии, а `ZB_REINSTALL=1` предварительно считает, хватит ли места.

## Диагностика

```sh
logread -e zeroblock | tail -50        # лог демона
cat /tmp/zeroblock-install.log         # лог установки
/etc/init.d/zeroblock status
uci show zeroblock | grep '=section$'  # секции маршрутизации
nft list ruleset | grep 0x40000000     # связка с zapret2
awg show awg10                         # состояние туннеля
```

### Проверить, что трафик реально идёт в обход

Не по DNS, а по фактическому адресу выхода. У секции MESSENGERS поднят mixed proxy на порту 2080 — с любой машины в сети:

```sh
curl --proxy http://192.168.1.1:2080 https://api.ipify.org   # через секцию
curl https://api.ipify.org                                    # напрямую
```

Адреса должны отличаться. Одинаковые — маршрутизация не работает.

### Нет ZeroBlock в меню LuCI

Обновите страницу, перелогиньтесь, очистите кэш браузера или откройте админку в инкогнито-окне. Если не помогло — проверьте, что пакет вообще стоит:

```sh
opkg list-installed | grep luci-app-zeroblock
opkg install luci-app-zeroblock   # если пусто
```

### Пропала секция маршрутизации

Симптом: часть сервисов перестала ходить в обход — например Telegram и Instagram, — хотя YouTube работает.

```sh
uci show zeroblock | grep '=section$'
```

Должны быть `awg10`, `opera` и `MESSENGERS`. Проще всего вернуть недостающее повторным запуском `install.sh` — он добавит и MESSENGERS из комплекта, и восстановит остальное из бэкапа.

Вручную из комплекта:

```sh
/etc/init.d/zeroblock stop
cat sections/MESSENGERS.conf >> /etc/config/zeroblock
uci show zeroblock >/dev/null && /etc/init.d/zeroblock start
```

### Веб-интерфейс есть, но настройки не применяются

Проверьте, не остались ли включёнными старые схемы — они конфликтуют за nftables:

```sh
for s in podkop passwall openclash xkeen v2raya; do
  [ -f /etc/init.d/$s ] && echo "$s: $(/etc/init.d/$s enabled >/dev/null 2>&1 && echo ВКЛЮЧЁН || echo выключен)"
done
```
